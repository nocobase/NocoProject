# Phase 1：内部可用 MVP

> 对应《NocoProject 产品与技术方案》第 6 章 Phase 1。目标：团队自己用它管理 NocoProject 的开发，连续两周派活、至少 50 条任务由 Agent 交付。
> 在 Phase 0 的骨架上继续，不返工。分三轮迭代，每轮三个并行子任务（服务端 / 守护进程与 CLI / 前端），共同契约在 `docs/phase1/iteration-N-contract.md`，类型追加到 `server/modules/shared/protocol.ts` 并复制到 `nocoproject-cli/src/protocol.ts`。

## 迭代划分

| 迭代 | 主题 | 内容 |
|---|---|---|
| 1 | 协作骨架 | 成员与角色、权限规则、项目（成员、可见性、仓库资源）、默认工作流模板、子任务与依赖与批次、执行者建议与委派名单、订阅与收件箱、标签与日期、看板、仓库 checkout、Codex 适配器、Agent 建子任务的 CLI |
| 2 | 交付链路 | GitHub 集成（PR 关联、卡片、合并后改状态）、批量录入（服务端 AI 解析）、审批门禁（临时实现）、富文本编辑器、表情与线程解决、Agent 环境变量加密与审计、技能挂载、用量统计页、Claude Code 真机校验、运行中插话（下一轮输入） |
| 3 | 打磨与自用 | 自定义工作流模板编辑器（只读展示 + 简单编辑）、任务描述批注、保存视图、全文搜索、安装文档、pnpm workspace 化与协议类型共享、性能与稳定性、两周 dogfooding 修缺陷 |

## 验收标准（整个 Phase 1）

- 非管理员成员登录后能看到并操作自己有权限的任务、项目、Agent；私有项目对非成员不可见（服务端强制，不是前端隐藏）。
- 一条父任务由 Agent 拆成带依赖和批次的子任务，被阻塞的子任务不入队，前置完成后自动放行，批次完成唤醒父执行者，全程在活动流可见。
- Agent 建的子任务指定其他 Agent 时进入负责人的"待我决定"，确认后才运行；命中委派名单时直接运行。
- 收件箱"待我决定"能承接：交付待验收、Agent 报 blocked、执行者建议、批次完成。
- 看板拖拽改状态，非法转换弹回；移出 backlog 时弹确认窗并可关闭"自行承接子任务"。
- Agent 在自己的 worktree 分支上工作，分支名出现在运行详情；PR 自动关联到任务，合并后任务按设置改状态。
- 批量录入：粘贴 20 条需求，AI 解析成草稿，预览修改后一次创建。
- Claude Code、Codex、OpenCode 三个适配器各至少一次真机闭环。

## 迭代 1 分工

| 子任务 | 主要交付 | 契约章节 |
|---|---|---|
| A 服务端 | 迁移 2（成员、项目成员与资源、工作流、标签、依赖、建议、订阅、收件箱、Agent 授权）；权限规则；工作流模板服务；触发规则扩展（依赖放行、批次完成、建议确认、委派）；收件箱与订阅；项目与标签接口；Agent 回写接口扩展（建子任务、项目上下文）；认领载荷扩展 | 契约 §A–§H、§K |
| B 守护进程与 CLI | 仓库 checkout（裸仓缓存 + worktree + 分支）；Codex 适配器；`issue create/children`、`project get`、`repo checkout` 子命令；简报新增章节；完成回报带分支 | 契约 §I、§K |
| C 前端 | 看板；任务详情升级（子任务、依赖、批次、标签、日期、建议卡、订阅、确认开始弹窗）；收件箱页；项目页；Agent 详情（访问范围、委派名单）；成员设置页；Phase 0 遗留界面问题 | 契约 §J |

顺序约束：C 依赖 A 的接口形状（契约给出）；B 依赖 A 的认领载荷与回写接口（契约给出）。三方只通过契约耦合，先改契约再改实现。
