# ADR-0003：临时实现隔离在接口之后，等待 NocoBase 官方能力

- 状态：已接受（2026-09-27）
- 关联：《方案》第 8 章

## 背景

两项能力 NocoBase 官方正在开发：工作流审批；活动流与变更事件（记录级钩子）。NocoProject 不能等，但也不能在这两项上积累自己的一套，否则官方发布后替换成本很高。

## 决定

1. 两项能力各自只通过一个接口进入业务代码：
   - `DomainEventBus`（`server/modules/shared/events.ts`）：进程内同步分发，所有写操作发事件，监听器只做入队或发失效信号。
   - `ActivityRecorder`（`server/modules/shared/activity.ts`）：把事件写成 `activities` 行，每行带 `eventId`。
   - `ApprovalGateway`（Phase 1 引入）：审批请求的创建、查询、通过、驳回。
2. 业务模块只依赖接口，不 import 具体实现类；事件名与审批状态枚举放在 `shared/contracts`，替换时不改。
3. 所有临时实现的文件头、表和迁移都带 `@temporary(nocobase-official)` 标记；仓库里有一个 grep 检查（Phase 1 加入 lint）。
4. 每个临时实现附一份"替换检查清单"测试：用假的官方实现跑现有测试，证明接口足够。

## 理由

- 让替换成为一次实现替换而不是一次业务重写。
- 活动流是产品的核心界面（任务时间线），不能因为等官方能力而缺席。

## 后果

- 短期多一层抽象；接口的形状可能与官方最终 API 不完全一致，替换时需要一个适配层。
- 事件总线是进程内的，多实例时不跨实例分发；这与官方能力发布前的 Phase 1 范围（单实例）一致。
