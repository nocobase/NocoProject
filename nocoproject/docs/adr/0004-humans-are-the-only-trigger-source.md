# ADR-0004：只有人和人配置的规则能唤醒 Agent

- 状态：已接受（2026-09-27）
- 关联：《方案》1.3 原则 2、2.5、2.6

## 背景

Multica 允许 Agent 在评论里 @ 其他 Agent、小队 leader 分派成员、Agent 之间形成回路。这带来两个问题：归因要靠七种来源的瀑布才能算清"谁授权了这次运行"；协作是否该结束全靠提示词，平台不知道。

## 决定

1. `trigger` 模块是唯一能创建运行的地方，规则表写在代码和文档里（`docs/phase0/protocol.md` §2）。
2. 能创建运行的动作只有：人的直接动作（分配执行者、移出 backlog、评论 @、回复 Agent、顶层评论路由给执行者）、人配置的规则（工作流阶段动作、自动化、子任务依赖放行、批次完成唤醒父执行者）、系统重试。
3. Agent 的评论永远不触发任何 Agent；Agent 为子任务指定其他 Agent 为执行者时变成"执行者建议"，由负责人确认，或命中人预先配置的委派名单。
4. 每次运行记录 `actorUserId`（承载谁的授权）和 `ownerUserId`（任务负责人）。因为每一跳都有人的决定，归因只有一跳。

## 理由

- 责任边界清楚：每次 Agent 动手都能指到一个人的动作或一个人配置的规则。
- 消灭 Agent 之间的无限回路，不需要靠提示词祈祷。
- 保留了"翻译文档交给便宜模型"这类场景，只是多了一次确认或一次性授权。

## 后果

- 需要一个"执行者建议"对象与收件箱"待我决定"的确认流程（Phase 1）。
- 任何新的触发来源都必须先改规则表和测试，再改代码。
