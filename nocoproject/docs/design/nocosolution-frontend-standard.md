# NocoSolution 前端标准

适用于所有 NocoSolution（NocoProject、NocoSupport、NocoCRM、NocoReach、NocoITAM 及后续 Solution）的前端。目标：用户在任何一个 Solution 里都认得出是一家的，"谁在做、AI 做到哪一步、哪里等我决定"的表达完全一致。

**优先级**：Solution 自己的产品设计决定 > 本标准 > 《NocoBase 3 应用前端交互最佳实践》（`docs/design/nocobase3-frontend-best-practices.md`，下称《最佳实践》）。偏离本标准的决定写进该 Solution 方案的"偏离总纲"一节。

本标准建立在《最佳实践》之上，那里已有的规则（页面框架、密度与预设、标签、表格、看板、表单、状态、文案、动效、键盘、多语言、可访问性）不在这里重复，只写 Solution 特有的部分。它是《NocoSolution 总纲》第 3 章（八条原则）、第 5 章（AI 产出五种形态）、第 8 章（界面规范）、第 10.2 节（六类指标）的前端落地。

组件名以 NocoProject 的实现为参照（`client/components/np-*`、`client/pages/np/**`）。在共享包 `@nocobase/solution-ui` 发布前，其他 Solution 按同样的结构和属性实现，换成自己的前缀，外观不得分叉；发布后改为直接依赖。

## 1. 侧栏骨架

所有 Solution 的侧栏按同一顺序平铺（分组规则见《最佳实践》§2.1）：

```
收件箱        ⑦    ← 琥珀色计数，只数"待我决定"的未读项
我的<对象>         ← 我的任务 / 我的工单 / 我的商机
──
<业务分组标签>     ← 工作 / 服务 / 销售 …
  <核心对象>       ← 任务 / 工单 / 商机
  <容器对象>       ← 项目 / 队列 / 客户
──
AGENT 团队
  Agent
  运行时 或 运行   ← 有本地守护进程的用"运行时"，服务端 Agent 用"运行"
  技能
  知识库
──
报表
设置
```

- 收件箱永远第一项；它的角标只数待我决定的项，通知不计入。
- "我的…"是第二项，页内用子路由标签分"我负责的 / 我执行的"，按"要我做什么"分组计数，不是数据库列表。
- 业务分组可以有多个，每组 2–5 项；分组标签用业务名词。
- Agent 团队分组的名称与四个入口在所有 Solution 中一致；没有的能力不留空入口。
- 搜索与新建不占侧栏入口：`⌘K` 与 `C` 全局可用，页头有对应按钮（搜索按钮带 `⌘K` 提示，主按钮带 `C` 提示）。
- 中文界面直接用"Agent"，不用"AI 员工"作主概念；用词以总纲附录 A 为准。

## 2. 收件箱

### 2.1 布局

```
┌ 收件箱 ─────────────────────────────────────────────── [搜索 ⌘K] [全部标为已读] ┐
│ 等你决定的事，以及你关注的对象的动态。                                          │
├──────────────────────────────┬───────────────────────────────────────────────────┤
│ [全部][待我决定 7][通知 47]  │ ◆ 待验收交付                        ✉  🗄  ↗   │ ← sticky 动作条
│               ○ 显示已归档   │ NP-64 登录页改版                                 │
│ 待我决定 7                   │ Echo 把它移到了待验收，请你验收。                 │
│ ┃◆ NP-64 待验收交付  2 小时  │ [验收通过] [打回并留言]  打开                     │
│ ┃  NP-64 登录页改版          │───────────────────────────────────────────────────│
│ ┃  Echo 把它移到了待验收…    │ NP-64 ●待验收 · 负责人 SA · 执行者 ▣ Echo        │
│  ✓ NP-52 审批     已处理     │ 被决定的完整内容（§2.3）                          │
│ 通知 47                      │ 最近 5 条动态                                    │
│  ● NP-61 新评论    1 小时    │                                                   │
│         [加载更多]           │                                                   │
│ J K 移动 · E 归档 · Enter 打开│                                                   │
└──────────────────────────────┴───────────────────────────────────────────────────┘
        26rem，自己滚动                         剩余宽度，自己滚动
```

- 主从布局（《最佳实践》§3.5）：左列 `26rem`，两列各自滚动。
- 过滤：`全部 / 待我决定 / 通知`（`?tab=`，默认全部），带计数；"显示已归档"开关（`?archived=1`）；选中项 `?item=`。
- 左列分两组：**待我决定**在前（其中仍待决定的排在已处理之前），**通知**在后；组标题带计数；每组游标分页。
- 卡片三行：类型图标 + 编号 + 类型 + 相对时间 / 对象标题（未读加粗 + 主色小圆点）/ 一句事实（`text-sm`，单行截断）。待决定项左侧琥珀色条；选中项左侧主色条 + 卡片底色。
- 选中即标为已读。实时推送的新卡片自上滑入；决定处理后原地变为"已处理"（55% 不透明度 + 绿勾）。
- 同一对象的通知合并为一张；同一父对象下的多条建议合并为一张卡，可批量处理；待决定项处理完自动归档。
- 窄屏先列表，点卡片进详情，详情左上角"返回"。

### 2.2 右列：sticky 动作条 + 完整上下文

- **动作条** `sticky top-0`：类型图标与名称、对象标题、一句事实、动作按钮；右侧图标按钮：标为已读 / 未读、归档、打开对象。需要留言的动作（打回、驳回）在动作条内展开评论框，`⌘Enter` 发送。
- **对象摘要**：编号、状态、负责人、执行者、运行中的 Agent（`NpLiveRun`）。
- **被决定的内容**：完整呈现，见 §2.3。
- **最近 5 条动态**：时间线的一行式条目（§6）。

### 2.3 每个决定都带完整上下文

决定永远和被决定的东西一起出现，动作紧贴内容下方。**不允许只有"接受"按钮而看不到接受的是什么。**

| 决定类型                         | 必须呈现的内容                                                                       |
| -------------------------------- | ------------------------------------------------------------------------------------ |
| 交付待验收                       | Agent 的交付说明全文（Markdown）、最近一次运行结果、交付物（PR 卡片、附件预览）      |
| Agent 受阻 / 失败退回            | 受阻原因（Agent 最近一条评论）、失败原因码的本地化说明、重试是否可行                 |
| 审批（状态变更、折扣、对外发送） | 变更 从 → 到、申请人、申请时间、理由；对外发送类附完整待发内容                       |
| 执行者 / 分派建议                | 每条建议单列，可逐条采纳或驳回                                                       |
| 内容建议（知识、回复草稿）       | 文档或草稿全文、理由、与当前版本的行级差异（绿增红删，长的未变段落折叠），可切换全文 |
| 字段冲突                         | 人填的值与 AI 的值并列、AI 的证据引文与来源时间                                      |
| 入口对象待接受                   | 对象预览（标题、来源、关键字段）与建议的负责人                                       |
| 待合并的外部产物                 | 产物卡片（PR、变更单）及其检查状态                                                   |

- 长内容在卡片内限高（`max-h-*` + 内部滚动或"展开"），不撑开整页。
- 有时限的决定在动作条显示倒计时。

### 2.4 动作按钮层级

| 动作                               | 样式                   |
| ---------------------------------- | ---------------------- |
| 推荐项（主动作）                   | 唯一的实心按钮，排第一 |
| 其他请求类动作                     | `outline`              |
| 驳回、拒绝                         | 红色（`destructive`）  |
| 导航（打开、改派、在收件箱中查看） | 文字按钮，排最后       |

- 每个决定 2–3 个明确选项；类型专属措辞放在 `<app>.decision.actions.<type>.<key>`（如交付的"验收通过 / 打回并留言"）。
- 收件箱与对象页共用同一个决定执行钩子（NocoProject：`useDecisionRunner`）：乐观地在所有缓存的收件箱列表里标为已处理，toast "已{{动作}}：{{标题}}"，失败回滚并重新拉取。
- 同类决定可批量处理；不选就什么都不发生。

## 3. 对象详情与"等你决定"

### 3.1 框架

核心对象详情用三栏（《最佳实践》§3.4，`NpDetailLayout`）：主栏为面包屑、标题、元信息行、"等你决定"、摘要与区块、时间线、吸底输入框；右栏 `20rem` 吸顶，自上而下为：属性、执行记录（进行中置顶）、建议、关联事项、参与者与关注者、详情、用量。

- 元信息行：编号（等宽）· 状态标签 · 所属容器；有运行中的运行时，行右侧显示 `NpLiveRun`，点击打开执行记录。
- 负责人在属性里排在执行者之前；负责人只能选真人成员。

### 3.2 "等你决定"区块

- 位置：主栏标题与元信息行下方、正文之前。
- 数据：当前用户在此对象上所有未处理的待决定项（收件箱接口按对象过滤，如 `GET /<app>/inbox?kind=decision&resolved=false&<object>Id=`）。
- 每条一张**决定卡**：琥珀色左边条 + 类型图标与标题 + 一句事实 + 相对时间 + **被决定的完整内容**（§2.3）+ 紧贴下方的动作行（§2.4）+ "在收件箱中查看"。对象页上不出现"打开对象"。
- 区块标题"等你决定"带计数；没有待决定项时整个区块不渲染。
- 本次访问里处理掉的卡片折叠成一行（"✓ 已验收通过"），可展开回看。
- 被决定卡覆盖的内容（审批卡、建议卡）不在下方区块重复出现。
- 与收件箱共用 `DecisionContent`、`DecisionActionsBar`、`useDecisionRunner`。

### 3.3 输入框与触发预览

- 输入框在主栏 `sticky bottom-0`；顶部两个标签：**评论 / 备注**（备注不唤醒任何人）。对外沟通的 Solution 再加"对外 / 内部"切换。
- **触发预览**：发送前在输入框下方用一行说明会唤醒谁、是否对外可见。会唤醒 Agent 时这一行用主色（"将唤醒 Claude-mac（执行者）"），对外可见时用琥珀色。
- 底行左侧"⌘ Enter 发送"，右侧主按钮。`@` 候选区分人与 Agent（头像形状）；@ Agent 不会让另一个 Agent 被唤醒，候选列表按触发规则标注。

## 4. AI 产出的五种形态

AI 的产出只以五种形态出现。每种形态一个共用组件，所有 Solution 同形同位。

| 形态     | 呈现位置                           | 组件                                     | 人的动作             |
| -------- | ---------------------------------- | ---------------------------------------- | -------------------- |
| 直接生效 | 时间线一行 + 字段旁来源标记        | `ActivityRow`、`SourceMark`              | 无；24 小时内可撤销  |
| 预填表单 | 标准新建 / 编辑表单或可编辑预览表  | 表单 + `SourceMark`、批量编辑器          | 核对、修改、点"创建" |
| 建议卡   | 对象右栏"建议"、建议页、首页汇总   | `SuggestionCard`                         | 接受 / 忽略          |
| 决定卡   | 收件箱"待我决定"、对象页"等你决定" | `DecisionContent` + `DecisionActionsBar` | 选一个选项           |
| 准备材料 | 挂在对象或行动上的文档             | `PreparedMaterial`                       | 使用 / 修改 / 丢弃   |

### 4.1 来源标记（五种形态共用）

每个由 AI 写入或填写的值旁边有来源标记：一个 `Sparkles` 小图标（`size-3.5 text-agent`），悬停或聚焦打开 `HoverCard`：

- 来源：Agent 头像与名字、所属运行（链接到执行记录）；
- 证据：引文（最多 3 条，带来源与时间），没有证据的值不允许出现；
- 状态："AI 直接写入"或"AI 填写，经 {{人}} 确认"；
- 撤销：直接生效的值在 24 小时内显示"撤销"，撤销即记为拒绝，此值不再提议。

### 4.2 直接生效

- 值已写入，字段正常显示，旁边带来源标记。
- 时间线记一行（§6.2）："▣ Echo 把 优先级 设为 高 · 3 分钟前 · 撤销"。
- 通知合并，不逐条打扰；不进"待我决定"。

### 4.3 预填表单

- 单条：打开标准的新建 / 编辑表单（`RouteDialog` 或 `RouteDrawer`）。AI 已填字段带来源标记；不确定的字段**留空**，字段下方琥珀色说明"请确认"；识别出的关联对象用表单顶部的 `Alert` 提示条列出，可一键关联。
- 多条：可编辑的预览表（§10），逐行校验标红，可删除、合并、调整层级。
- 提交按钮写具体数量与动作（"创建 12 个任务"），始终由人点击；AI 从不替人提交。

### 4.4 建议卡

```
┌ 建议 ───────────────────────────────────── 3 ┐
│ ▣ Echo · 2 小时前                             │
│ 把执行者改为 Codex：前端改动已由它完成两次。   │  ← 一句结论
│ ▸ 依据（2）                                   │  ← Collapsible，展开看引文
│ [接受]  忽略                                   │
└───────────────────────────────────────────────┘
```

- 卡片 `rounded-lg border bg-card p-3`；一句话结论 `text-sm`；依据默认折叠。
- 两个键：`接受`（`outline` 或 `sm` 实心，视所在区域是否已有主按钮）与 `忽略`（文字按钮）；忽略可选原因（下拉，非必填）。
- 同类多张时区块标题右侧有"全部接受"。
- 键盘：`J` / `K` 移动，`Enter` 接受，`X` 忽略。接受立即生效并 toast，toast 内带"撤销"。
- 没有建议时区块不渲染。

### 4.5 决定卡

见 §2.3、§2.4、§3.2。每张卡只问一件事；推荐项高亮为第一个实心按钮；附依据；有时限的显示倒计时。

### 4.6 准备材料

- 挂在对象的区块或行动上，标题旁一个 `NpTag tone='violet'`"已准备好"。
- 打开即是可编辑正文（富文本 / Markdown 编辑器，`⌘Enter` 保存）；文件类材料用文件预览（DOCX / XLSX / PPTX / PDF）。
- 动作：`使用`（主动作，如"插入回复""发送前审阅"）、`编辑`、`丢弃`（可写一句原因，回流给 Agent）。
- 邮件草稿存入本人邮箱的草稿箱，界面显示"已存入草稿箱"与打开链接。

### 4.7 Copilot 面板不是第六种形态

页面右侧可展开的 Copilot 面板是 AI 员工插件的聊天面板挂上页面上下文；面板里的对话不进时间线，结论通过"写回"生成上面某一种形态。

## 5. 执行者：人、Agent、系统

### 5.1 头像

所有出现人、Agent、系统的位置只用 `NpActorAvatar`，形状与颜色双编码：

| 执行者 | 形状                     | 颜色                          | 内容       |
| ------ | ------------------------ | ----------------------------- | ---------- |
| 人     | 圆形                     | `bg-muted`                    | 姓名首字母 |
| Agent  | 圆角方形（`rounded-md`） | `bg-agent/15 text-agent`      | `Bot` 图标 |
| 系统   | 圆形虚线描边             | 透明，`text-muted-foreground` | `Cog` 图标 |

- 尺寸：`xs` 16px（行内与文字并排）、`sm` 24px（列表）、`default` 32px（页头）。
- 读屏：独立头像读作"名字（Agent）"；与可见名字并排时头像为装饰，名字后接 `sr-only` 的"（Agent）"。
- `--agent`（紫罗兰）只用于 Agent 身份，不用于别处。

```tsx
<NpActorAvatar
  type='agent'
  name='Echo'
  size='sm'
  showName
  live={run?.status === 'running'}
/>
```

### 5.2 运行中指示

- **Agent 正在运行**时，它的头像外圈加主色呼吸环（`live`，1.6s，减少动态效果时变为静态描边）。
- `NpLiveRun`：带边框的小胶囊，Agent 头像（呼吸）+ "Echo 正在工作 · 3 分钟"，主色文字；排队或延后时灰色"Echo 排队中"。出现在对象元信息行、收件箱对象摘要里。
- 看板卡片上 Agent 运行中：卡片左侧 2px 主色条 + `NpPulse`"工作中"。
- 执行者是 Agent 时，属性栏显示头像 + 名字 + "Agent"标签，以及当前状态：工作中 / 等待审批 / 等待客户。
- 负责人与执行者同时出现时，负责人在前。

## 6. 时间线

对象页的时间线把系统条目、运行、评论与 Agent 的交付放在同一条流里，按时间正序，超过 100 条虚拟化，更早的条目游标加载。

### 6.1 三种条目

| 条目                   | 形态                                      | 内容                                                                                                    |
| ---------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| 系统条目、直接生效     | **一行**，`text-sm text-muted-foreground` | 图标 + `xs` 头像 + 执行者名（`font-medium text-foreground`）+ 动作 + 从 → 到的标签 + 右侧相对时间       |
| 运行                   | **一行**                                  | 运行中为 `NpPulse`，否则 `Play` 图标 + "Echo 完成了运行" + 触发原因 + 失败原因（红）+ "查看记录" + 时间 |
| 人的评论、Agent 的卡片 | **卡片**，`rounded-lg border bg-card`     | 见 §6.2                                                                                                 |

### 6.2 Agent 卡片

```
┌ ▣ Echo  Agent  交付说明                                        1 小时前 ┐
│ 已完成：PR #2（已关联）                                                   │  ← 摘要，Markdown
│ 改动 … 验证 …                                                   [展开]    │  ← 超过限高折叠
│ ▸ 运行记录 · 已分配 · 9 分 39 秒 · 42 次工具调用                          │  ← Collapsible
│ ▸ 依据（3）                                                               │  ← 引文、文件、链接
│ 回复 · 解决                                                               │
└───────────────────────────────────────────────────────────────────────────┘
```

- 头部：Agent 头像与名字、"Agent"标签、卡片类型（交付说明、受阻说明、分析）、时间。
- 摘要：Markdown 正文，超过限高折叠，"展开"查看全文。
- 运行记录：默认折叠；展开后是逐条事件（工具调用一行摘要，可再展开看输入输出），与"查看记录"的完整回放同源。
- 依据：引文列表，每条带来源与时间。
- 人的评论是可回复、可表情回应、可解决的讨论串；备注（`/note`）带"备注"标记，不唤醒任何人。

## 8. 运行、用量与成本

### 8.1 执行记录卡（对象右栏）

- 标题"执行记录"，进行中的运行置顶。
- 每条：`NpRunStatusBadge` + Agent 名 + 相对时间；下方两列"标签 — 值"：触发原因、开始、结束 · 时长、分支或目标（等宽）。
- 动作："查看记录"打开完整回放（子路由 `runs/:runId`）；运行中可"取消"（`AlertDialog` 确认）；失败且原因可重试时可"重试"。
- 失败原因显示原因码的本地化文案（红色），不显示原始报错。

### 8.2 用量卡（对象右栏）

两列"标签 — 值"，全部 `tabular-nums`：

| 行                 | 格式                                   |
| ------------------ | -------------------------------------- |
| 运行次数           | 整数                                   |
| 输入 / 输出 / 缓存 | token 缩写：`56`、`15.9K`、`1.5M`      |
| 估算成本           | 货币格式，如 `$0.97`；标签写"估算成本" |

- 成本按设置里的模型价格表估算；价格缺失的模型显示 "—" 并在悬停说明。
- 用量上限：进度条显示本期已用，≥ 80% 琥珀色，达到上限红色并显示"已暂停"。

### 8.3 Agent 列表与详情

- 列表列：名称（头像 + 名字）、职责、模型（等宽）、访问范围、本月用量、接受率 / 通过率、失败率。
- 详情：指令（显示源码默认值与当前值）、技能、工具与审批、自治矩阵（动作 × 自动 / 建议 / 审批 / 人）、用量上限、最近运行回放。

### 8.4 报表的用量标签页

按 Agent、按对象、按人、按日的汇总表；日期范围与范围筛选在 URL；数字右对齐。

## 9. 会话模式对话面板

对象可在属性里切换"会话模式：任务 / 对话"。

- **任务**（默认）：Agent 按触发规则逐次运行，产出进时间线。
- **对话**：执行面板变为与执行者 Agent 的逐轮对话：
  - 人的顶层评论显示为消息，Agent 的回合实时流式显示，工具调用为可展开的一行事件；
  - 下方是消息框（支持 `@` 与 `/note`），`⌘Enter` 发送；
  - Agent 工作中，面板顶部显示"Echo 正在工作"，消息框下提示"Agent 正在工作，新消息会在本轮结束后发送"，并显示排队条数；
  - 空状态一句："发送一条消息开始对话。"
- 对话中的每条消息都是对象上的评论，照常进时间线；会话模式不是独立的聊天产品。
- 与 Copilot 面板区分：Copilot 对话不进时间线（§4.7）。

## 10. 批量录入

批量新建一律通过 AI 解析、人确认，AI 不可用时回退到规则，人工录入始终可用。

- **入口**：列表页与容器对象页头的次要按钮"批量添加"，打开加宽的 `RouteDrawer`（`sm:max-w-5xl`，子路由如 `/<objects>/intake`）；从容器进入时预选该容器。对象详情的"AI 拆解"打开同一个编辑器，草稿成为子对象。
- **粘贴**：一个 `Textarea` 接受清单、会议纪要、CSV；下方一行写规则语法（标题行成为父项、缩进成为子项、`[high]`、`#标签`）。按钮"拆成草稿"。
- **解析**：配置了模型时用 AI 解析；AI 不可用或失败时按规则拆分，并在草稿上方显示 `Alert`："AI 解析不可用，已按规则拆分，请检查草稿。"设置里可选"自动 / 仅规则"。
- **草稿表**（预填表单的多条形态）：每行标题、优先级、标签、阶段、父项、执行者、负责人；逐行校验，问题标红并在行尾列出；可缩进 / 提升、删除、"添加一行"；表上方设置批次负责人与默认执行者。
- **提交**：主按钮"创建 N 个<对象>"；次要"保存草稿"；"放弃本批"。批次 id 在 `?batch=`，刷新不丢。
- **撤回**："我最近的批次"列表里可撤回一批，`AlertDialog` 写明后果："本批创建的任务会被删除；Agent 已经执行过的任务会保留。"
- 单条新建（`C`、页头主按钮）始终独立可用，不依赖 AI。

## 11. 列表与看板的 Solution 增补

- 核心对象列表页默认看板（列来自阶段模板），视图选择记住（《最佳实践》§8）。
- 拖拽改状态由服务端状态机裁决：非法转换弹回并说明原因；会触发运行的转换先弹确认，确认框写明将唤醒谁。
- 看板或列表上方可有一条汇总条："N 个 Agent 工作中 · M 条等你决定"，点击分别筛选。
- 卡片底行：负责人头像 + 执行者（Agent 带呼吸环）+ 截止日或更新时间。

## 12. 设置

- 设置在**产品侧**：侧栏最后一项"设置"，是普通应用路由（如 `/config`），不在系统外壳的 `/settings` 下。系统外壳只放平台级设置（用户、认证、权限集、API Key、插件）。
- 页内标签是子路由，按以下顺序取用所需项：通用、成员、阶段模板（或工作流）、标签、集成（代码托管、邮箱、IM）、模型价格、指标目标。
- 每个主题一张卡片、各自保存；开关即时生效并 toast；需要输入的在点"保存"时生效。
- 阶段模板编辑器与看板用同一套状态组件与色表；路由、桥接、信号等规则编辑器提供"用一条历史记录试跑"。
- 密钥类输入框只显示是否已设置，不回显值；更换需重新输入。
- 自治矩阵在 Agent 详情里编辑，组织单元级默认值在设置里。

## 13. 报表页

报表页 `/reports`，子路由标签：**指标 / 用量**。

```
报表
与 Agent 协作的验收指标，以及运行的 token 与成本。
[指标] [用量]
[全部项目 ▾] [📅 8月29日 – 9月27日]
● 全部达标   目标在 设置 → 通用 中设置。
采用 ─────────────────────────────────────────────
一句说明
┌ 连续自用周数 ┐ ┌ 活跃天数 ┐ ┌ 新建数 ┐ ┌ 活跃成员 ┐
AI 承担率 ────────────────────────────────────────
┌ Agent 完成占比 100%  ●达标 目标 ≥ 50% ┐ …
信任 · 可靠 · 成本 · 人的负担 …
```

- 工具栏：范围筛选（项目 / 队列 / 组织单元）+ `DateRangePicker`（默认最近 30 天），都在 URL。
- 顶部一个汇总标签：全部达标（green）或"N 项未达标"（amber），后接一句目标在哪里设置。
- **六类固定顺序**，每类一个分区（标题 `text-sm font-semibold` + 一句说明）：

  | 类        | 典型指标                                             |
  | --------- | ---------------------------------------------------- |
  | 采用      | 连续自用周数、活跃天数、新建数、活跃成员             |
  | AI 承担率 | 由 Agent 完成的占比与数量                            |
  | 信任      | 建议接受率、审核通过率、冲突中 AI 正确率、改动幅度   |
  | 可靠      | 丢失计数（运行、邮件、消息）、失败率、领取与处理时延 |
  | 成本      | 每对象成本、每 Agent 月用量                          |
  | 人的负担  | 待我决定数量、处理时长（p50）、交接率                |

- 指标卡网格 `grid gap-4 sm:grid-cols-2 xl:grid-cols-4`；卡片：指标名、大号数值（`text-2xl tabular-nums`）、有目标的带状态标签与"目标 ≥ 50%"、`Info` 图标悬停显示计算口径。
- 无法计算时数值 "—"，状态"暂无数据"。
- 明细表紧跟所属分区：失败按原因码（可靠）、成本按 Agent（成本）、决定按类型（人的负担）。
- 指标键名与格式在所有 Solution 中一致，保证可比。
