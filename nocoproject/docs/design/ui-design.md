# NocoProject 界面设计系统

版本 1.1（2026-09-27）。适用于 `client/pages/np/**` 与它们共用的 `client/components/np-*`、`page-header`、`page-container`、`data-table*`，以及应用外壳的侧边栏。本文是设计决定的唯一来源；`client/pages/np/README.md` 是它的实现规则摘要，两者冲突以本文为准并同步修正 README。

## 0. 为什么要重做

迭代 1–3 把功能做全了，但界面像草稿：

- **没有视觉层次**：主色是近黑，按钮、选中项、运行中、待决定全都是同一种黑白，眼睛找不到"现在该看哪"。
- **颜色语义错乱**：标签和状态的七种颜色映射到 `chart-1..5`，而浅色和深色主题里 `chart-N` 是完全不同的色相（"紫色"在浅色里是琥珀色、在深色里是粉色）。
- **决定没有上下文**：收件箱卡片上直接放"接受 / 要求修改"，但看不到 Agent 交付了什么；任务详情页反而没有"等你验收"的提示。
- **在 compact 预设下过密**（见 §4）：侧栏入口、顶栏图标、表格行都被压扁。
- **框架不统一**：页面标题 30px 负字距、详情页 24px；卡片有的有边框有的没有；侧边栏分组可折叠导致入口时隐时现；项目详情主栏只有一行看板、右栏塞满表单；空的区块（无 PR、无子任务、无依赖）各占一整块。

设计目标（产品负责人原话）：**高效、有质感、又不失灵动活泼**。可执行的原则：

1. **安静的底，活的信号**。界面大部分是中性灰阶；颜色只留给：主要动作与正在发生（靛蓝）、需要你（琥珀）、以及语义标签（淡色胶囊）。
2. **决定就地完成，且看得见被决定的东西**。任何"等你决定"的时刻，被决定的完整内容（交付说明、PR、建议正文、状态变化）和动作出现在同一视野，动作紧贴内容下方。
3. **谁在动一眼可见**。人、Agent、系统三种执行者形状和色调都不同；Agent 正在运行时，它的头像在呼吸。
4. **一个框架走到底**。同一种页头、卡片、表格、标签、空状态。
5. **动效只解释变化**。新东西滑入、处理完的东西变淡、运行中的东西脉动；尊重"减少动态效果"。
6. **文字陈述事实与动作，不解释界面**（§9.3）。

参考：兄弟产品 NocoSupport 工单详情的"等人决定"区块（决定 + 完整内容 + 紧贴的动作），以及 NocoBase Hub 的淡色标签。

## 1. 布局系统

### 1.1 外壳

```
┌────────────┬──────────────────────────────────────────────────────────┐
│ 品牌       │ 顶栏：折叠按钮 │ 工作区名称                外观 · 账户   │
│────────────┼──────────────────────────────────────────────────────────┤
│ 收件箱  ⑦  │                                                          │
│ 我的任务   │   页面内容                                               │
│            │                                                          │
│ 工作       │                                                          │
│ 任务       │                                                          │
│ 项目       │                                                          │
│            │                                                          │
│ AGENT 团队 │                                                          │
│ Agent      │                                                          │
│ 运行时     │                                                          │
│ 技能       │                                                          │
│ 知识库     │                                                          │
│            │                                                          │
│ 报表       │                                                          │
│ 设置       │                                                          │
└────────────┴──────────────────────────────────────────────────────────┘
```

顶栏、侧栏宽度与图标按钮沿用模板尺寸（顶栏 `h-16`，图标按钮 `size-10` / `size-9`），它们本来就是按 compact 预设设计的，不再另行压缩。

### 1.2 侧边栏（要求 a）

- **分组永不折叠**。没有自己页面的顶层分组（工作、Agent 团队）渲染为一行小号灰色分组标签（`text-xs font-medium text-muted-foreground`，英文大写加字距），入口始终列在下面。实现：`client/layouts/components/navigation-sections.tsx`；设置和开发者布局仍用模板的可折叠树。
- 顺序按方案 §3.1：收件箱、我的任务；**工作**：任务、项目；**Agent 团队**：Agent、运行时、技能、知识库；报表；设置。分区之间 `gap-5`，入口之间 `gap-1`。
- 入口保留模板的行尺寸（`px-3 py-2 gap-3`，compact 下约 32px、default 下约 36px），图标 16px；未选中图标为 `text-muted-foreground`，选中项底色 `bg-sidebar-primary`、文字加粗、图标变主色。
- **收件箱角标**：行右端的琥珀色计数胶囊（`bg-attention`），只数待我决定的未读项，超过 99 显示 `99+`；侧栏折叠为图标模式时移到图标右上角。

### 1.3 页面框架

```
┌──────────────────────────────────────────────────────────────┐
│ 标题 text-2xl/semibold                         [次要] [主要] │
│ 一句话说明 text-sm muted                                     │
└──────────────────────────────────────────────────────────────┘
  页内标签（下划线，选中为主色）
  工具栏（搜索 / 筛选 / 视图切换）
  内容（表格 / 看板 / 卡片）
```

- `PageContainer`：`p-6 md:p-8`，区块 `space-y-6`，不限宽。
- `PageHeader`：标题 `text-2xl font-semibold tracking-tight`，说明 `text-sm text-muted-foreground`，动作右侧垂直居中；一页最多一个实心主按钮，放在最右。
- 页内标签：页面级用子路由（`NpRouteTabs`）；覆盖式详情页的分区用 `NpTabBar` + `?tab=`（详情页的子路由留给它的弹窗）。两者外观相同。

### 1.4 记录详情（三栏）与滚动

```
┌────────┬───────────────────────────────────────────────┬────────────────┐
│ 侧栏   │ 面包屑                                        │ ┌ 属性 ──────┐ │
│        │ 标题 text-2xl                               ✎ │ │ 状态 负责人 │ │
│        │ NP-64 ●待验收 · 项目     (◉▣ Echo 工作中 3分) │ │ 执行者 …    │ │
│        │ 等你决定                                      │ └────────────┘ │
│        │ ┃ ◆ 待验收交付                                │ ┌ 运行记录 ──┐ │
│        │ ┃ 交付评论全文 …   PR 卡片                    │ └────────────┘ │
│        │ ┃ [验收通过] [打回并留言]    在收件箱中查看   │ ┌ 参与者 ────┐ │
│        │ 描述                                          │ └────────────┘ │
│        │ 子任务 · 无  [AI 拆解] [+ 新建子任务]         │                │
│        │ 添加 (+前置依赖) (+关联 PR)                   │                │
│        │ 活动                                          │                │
│        │ ──────────────────────────────────────────── │                │
│        │ [评论][备注] 评论框（吸底）                   │                │
└────────┴───────────────────────────────────────────────┴────────────────┘
```

- 主栏 `flex-1 min-w-0`，右栏固定 `20rem`（用 rem 写死，compact 不会把它压窄），底色 `bg-muted/30`，里面是一摞小卡片；`lg` 以下折成一栏。
- **只有一个滚动容器**：整个覆盖页一起滚动，主栏和右栏都不单独滚动；评论框在主栏里 `sticky bottom-0`。桌面宽度下右栏的卡片 `sticky top-0` 于页头下方跟随，右栏高于视口时不吸附、随页面滚动（`NpDetailLayout` 量高度决定，不给右栏第二个滚动条）。项目详情、知识详情同理。收件箱的主从两栏是例外（列表和详情各自滚动，这是主从布局的本意）。
- 区块之间 `space-y-6`；块标题统一 `NpSectionHeading`（`text-sm font-semibold` + 计数 + 右侧动作）。

### 1.5 卡片、表格与视口

| 用卡片                                                               | 用表格                                                                      |
| -------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| 一眼看"状态 + 谁 + 下一步"的对象：看板卡、收件箱卡、决定卡、项目数字 | 横向比较多个属性、排序、批量操作：任务列表、项目、Agent、运行时、技能、成员 |

- **卡片**：`rounded-lg border bg-card`，内边距 `p-4`（区块卡）/ `p-3`（紧凑列表项）；悬停只变边框色，拖拽时才有阴影。
- **表格**：外框 `rounded-lg border bg-card`，表头 `bg-muted/40`、文字 `text-muted-foreground`，行高沿用 `DataTable` 默认；可点击行悬停 `bg-muted/50`。
- **列宽封顶**：列定义用 `meta.className` 给宽度。标题列取剩余宽度但可收缩（`w-full max-w-0`），内容单行截断、最长 30rem、悬停显示全文；编号、状态、优先级、负责人、执行者、日期列给固定宽度。一个长标题永远撑不开表格。
- **排序**：可排序的表头点击即排序，升序 → 降序 → 取消循环，图标反映状态；表头上不再有下拉菜单，隐藏列放在"视图"菜单（`DataTableViewOptions`）。
- **视口**：任务页与我的任务页 = 页头 + 工具栏 + 内容区，内容区占满剩余高度、页面本身不滚动。看板各列各自纵向滚动、列与列横向滚动；表格在固定高度区域内滚动、表头吸顶，"加载更多"固定在表格下方（`DataTable fillHeight`、`IssueBoard fill`）。

## 2. 颜色

### 2.1 中性色（主题预设 `client/theme/themes/{compact,default}.css`）

底色带极轻的冷调（色相 264、色度 ≤ 0.014），深色主题是石墨灰而不是纯黑，卡片比底色亮一档、弹层再亮一档，靠明度而不是阴影分层。

| 令牌                 | 浅色                       | 深色                     |
| -------------------- | -------------------------- | ------------------------ |
| `--background`       | `oklch(0.985 0.002 264)`   | `oklch(0.155 0.006 264)` |
| `--card`             | `oklch(1 0 0)`             | `oklch(0.195 0.007 264)` |
| `--foreground`       | `oklch(0.2 0.012 264)`     | `oklch(0.95 0.004 264)`  |
| `--muted-foreground` | `oklch(0.5 0.014 264)`     | `oklch(0.7 0.012 264)`   |
| `--border`           | `oklch(0.915 0.004 264)`   | `oklch(1 0 0 / 9%)`      |
| `--primary`          | `oklch(0.52 0.2 266)` 靛蓝 | `oklch(0.7 0.15 268)`    |
| `--sidebar`          | `oklch(0.975 0.003 264)`   | `oklch(0.175 0.006 264)` |

`--chart-1..5` 固定为同一套色相（橙 / 绿 / 蓝 / 黄 / 紫），浅深只调明度，图表与旧的颜色名不再错位。

### 2.2 应用自己的语义色（`client/np-tones.css`）

这些不是主题预设令牌，而是 NocoProject 自己的：两个预设、两种模式共享，`client/styles.css` 把它们映射成 Tailwind 颜色。

| 令牌                                     | 用途                                                                          |
| ---------------------------------------- | ----------------------------------------------------------------------------- |
| `--agent`                                | Agent 身份色（紫罗兰），只用于 Agent 头像                                     |
| `--attention` / `--attention-foreground` | "需要你"：收件箱计数、决定卡左侧色条与图标                                    |
| `--success`                              | 成功标记（已处理、已完成）                                                    |
| `--np-tint-<色>` / `--np-ink-<色>`       | 标签的淡底 / 深字，八种：grey、blue、violet、amber、green、slate、red、orange |

### 2.3 执行者

| 执行者 | 形状         | 颜色                     | 内容       |
| ------ | ------------ | ------------------------ | ---------- |
| 人     | 圆形         | `bg-muted`               | 姓名首字母 |
| Agent  | 圆角方形     | `bg-agent/15 text-agent` | 机器人图标 |
| 系统   | 圆形虚线描边 | 透明                     | 齿轮图标   |

形状 + 颜色双编码；屏幕阅读器读出"名字（Agent）"。Agent 正在运行时头像外圈加主色呼吸环（`NpActorAvatar live`）。

### 2.4 标签：淡色胶囊（`NpTag`）

所有标签都是同一个组件 `NpTag`：圆角胶囊、淡色底（该色相约 10–15% 的明度底，深色模式为半透明的暗淡色）+ 同色相的深色文字，13px（`badge-text`），左右留足内边距；状态类标签带一个同色小圆点。**不用实心填充，也不用"中性胶囊 + 小圆点"。** 一张颜色表（`NP_TONE_CLASS`）按语义取色：

| 语义                                               | 色                                                               |
| -------------------------------------------------- | ---------------------------------------------------------------- |
| 状态：未开始（待规划、待开始）                     | grey                                                             |
| 状态：进行中                                       | blue                                                             |
| 状态：待验收                                       | violet                                                           |
| 状态：受阻                                         | amber                                                            |
| 状态：已完成                                       | green                                                            |
| 状态：已取消                                       | slate                                                            |
| 优先级：紧急 / 高 / 中 / 低                        | red（带警示图标）/ orange / blue / grey；无优先级显示 "—"        |
| 项目状态：计划中 / 进行中 / 暂停 / 已完成 / 已取消 | grey / blue / amber / green / slate                              |
| PR：打开 / 草稿 / 已合并 / 已关闭                  | green / grey / violet / slate                                    |
| 运行：运行中（脉冲）/ 完成 / 失败 / 取消 / 排队    | blue / green / red / slate / grey                                |
| 标签（用户自定义颜色名）                           | gray→grey、red、orange、yellow→amber、green、blue、purple→violet |
| 角色与标记：Agent、来自建议、默认工作流、需审批    | violet、violet、blue、amber                                      |

状态色按**语义**而不是工作流里的颜色名取（`statusTone`）：自定义的"进行中"类状态若工作流标为紫色视为待验收、标为红/橙视为受阻，其余为蓝。看板列头和项目状态分布条用同一色相的深色圆点（`NP_TONE_DOT_CLASS`）。

### 2.5 决定的紧迫度

| 程度   | 场景                                                          | 表现                                |
| ------ | ------------------------------------------------------------- | ----------------------------------- |
| 需要你 | 交付待验收、Agent 受阻、审批、执行者建议、知识建议、PR 待合并 | 琥珀色条 + 琥珀图标 + 实心主按钮    |
| 知会   | 评论、@、状态变化、分配                                       | 无色条；未读时标题加粗 + 主色小圆点 |
| 已处理 | 决定已完成                                                    | 55% 不透明度 + 绿色勾 + "已处理"    |

## 3. 字体与排版

系统字体栈（含苹方、微软雅黑）。字号来自主题令牌；唯一例外是标签的 13px（`badge-text`，定义在 `np-tones.css`）。

| 角色                               | 类                                                                   |
| ---------------------------------- | -------------------------------------------------------------------- |
| 页面标题                           | `text-2xl font-semibold tracking-tight`                              |
| 记录标题                           | `text-2xl font-semibold tracking-tight`                              |
| 区块标题                           | `text-sm font-semibold`                                              |
| 正文（含卡片说明句、区块说明）     | `text-sm`                                                            |
| 说明性元信息（时间、计数、编号行） | `text-xs text-muted-foreground`                                      |
| 标签                               | `NpTag`（13px）                                                      |
| 分组标签                           | `text-xs font-medium text-muted-foreground uppercase tracking-wider` |
| 标识符                             | `font-mono text-xs text-muted-foreground`                            |
| 数字                               | `tabular-nums`                                                       |

`text-xs` 只用于说明和元信息，正文一律 `text-sm`。

## 4. 样式规范：为什么 compact 下会显得过密、以后怎么写样式

**根因。** NocoBase 要求 compact 为默认预设（`client/theme/theme-presets.ts`）。compact 把 `--spacing` 设为 `0.2rem`，比 Tailwind 默认的 `0.25rem` 小 20%，于是所有 `p-*`、`gap-*`、`h-*`、`w-*` 都按比例缩小。我们的页面原本就挑了偏紧的数值（`h-8` 的导航行、`size-8` 的图标按钮、`w-72` 的看板列），再加上 `text-xs` 用了 122 次，在 compact 下一乘 0.8 就挤成一团。模板和参考页（`client/pages/reference/examples`）是按 compact 设计的，所以它们看起来正常。

**以后怎么写：**

1. 永远不在页面里覆盖 `--spacing` 或其他预设令牌，也不为某一页单独改密度。
2. 尺寸用间距刻度和组件的尺寸变体，不手挑紧凑值：按钮用 default / `sm` / `icon-sm`，导航沿用模板行尺寸，表格用 `DataTable` 默认行高，卡片 `p-4` / `p-5`。
3. 正文 `text-sm`；`text-xs` 只给说明、元信息；标签用 `NpTag`。
4. 点击目标不小于 `icon-sm`（compact 下仍可用）。
5. 以参考页为密度基准：写之前先看 `client/pages/reference/examples` 里同类区块用的尺寸。
6. 布局性的固定宽度（右栏 20rem、收件箱列表 26rem、看板列 18rem）用 rem 写死，并在代码里注明，因为 `w-80` 这类宽度会被 compact 缩小。
7. 每次改动在 compact 和 default 两个预设、浅深两种模式下都看一遍。

## 5. 图标

- 统一 `lucide-react`；行内 `size-3.5`、按钮内用 `data-icon`、空状态由 `NpEmpty` 决定尺寸。
- 收件箱类型图标（`InboxTypeIcon`）：交付 `PackageCheck`、受阻 `OctagonPause`、审批 `ShieldCheck`、执行者建议 `Users`、知识 `BookOpenText`、PR `GitPullRequest`、评论 `MessageSquare`、@ `AtSign`、状态变化 `ArrowRightLeft`、运行失败 `AlertTriangle`（红）；待决定时为琥珀色。
- 紧急优先级带 `AlertTriangle`；运行中用 `NpPulse`；已处理用 `CheckCircle2`。

## 6. 动效

原则：只解释"发生了什么变化"，150–300ms，`ease-out`，全部可被"减少动态效果"关闭。

| 场景                     | 动效                                                   | 实现                                                           |
| ------------------------ | ------------------------------------------------------ | -------------------------------------------------------------- |
| 实时推送来的新收件箱卡片 | 自上滑入 + 淡入 200ms                                  | `animate-in fade-in slide-in-from-top-1`（首屏已有的卡片不动） |
| 决定处理完成（乐观更新） | 卡片降到 55% + 绿勾，200ms                             | `transition-opacity`                                           |
| 任务页决定卡             | 出现时淡入；处理后折叠成一行"✓ 已验收通过"，可展开回看 | `Collapsible`                                                  |
| 运行中                   | 主色光晕脉冲；Agent 头像外圈 1.6s 呼吸环               | `NpPulse`、`np-live-ring`                                      |
| 进度环                   | 数值变化时描边 300ms 过渡                              | `NpProgressRing`                                               |
| 拖拽看板卡               | 抬起 `shadow-md` + 描边；目标列底色加深                | dnd-kit                                                        |
| 乐观状态切换             | 先改界面、后发请求；失败回滚并 toast                   | TanStack Query                                                 |

## 8. 关键页面

### 8.1 收件箱：主从布局（要求 b）

```
┌ 收件箱 ─────────────────────────────────────────────────── [全部标为已读] ┐
│ 待我决定和你关注的任务动态。                                              │
├───────────────────────────────┬───────────────────────────────────────────┤
│ [全部][待我决定 7][通知 47]    │ ◆ 待验收交付               ✉ 🗄 ↗        │ ← 吸顶动作条
│                ○ 显示已归档    │ NP-64 kb read …                          │
│ 待我决定 26                    │ Echo 把它移到了待验收，请你验收。          │
│ ┃◆ NP-64 待验收        2 小时  │ [验收通过] [打回并留言]  打开             │
│ ┃  NP-64 kb read …             │───────────────────────────────────────────│
│ ┃  Echo 把它移到了待验收…      │ NP-64 ●待验收  负责人 SA  执行者 ▣ Echo   │
│  ✓ NP-52 审批 已处理           │ ▣ Echo 交付说明                  2 小时   │
│ 通知 47                        │ ┌ 交付评论全文（Markdown）─────────────┐ │
│  ● NP-61 新评论        1 小时  │ └──────────────────────────────────────┘ │
│    …                           │ PR 卡片                                   │
│          [加载更多]            │ 最近动态（5 条）                          │
│ J K 移动 · E 归档 · Enter 打开 │                                           │
└───────────────────────────────┴───────────────────────────────────────────┘
          26rem，自己滚动                   剩余宽度，自己滚动
```

- 左列：两组（待我决定在前、其中仍待决定的排在已处理之前；通知在后），组标题带计数；卡片三行：类型图标 + 编号 + 类型 + 时间 / 标题（未读加粗 + 主色点）/ 一句说明（`text-sm`，单行）。待决定左侧琥珀色条，选中项左侧主色条 + 卡片底。
- 过滤：`全部 / 待我决定 / 通知`（`?tab=`，默认全部），显示已归档（`?archived=1`），选中项（`?item=`）。
- 右列：选中项的完整上下文，吸顶动作条（类型、标题、一句事实、`payload.actions`；需要留言的动作在条内展开评论框，⌘Enter 发送；右侧图标按钮：标为已读/未读、归档、打开任务）。下面是任务摘要（编号、状态、负责人、执行者、运行中的 Agent）、**被决定的内容**（见 §8.2 表）、最近 5 条动态。
- 键盘：`j` / `k` 移动、`e` 归档（并移到下一条）、`Enter` 打开任务；输入框内与弹窗打开时不响应。
- 小屏：先列表，点卡片进详情，详情左上角"返回"。
- 选中即标为已读；实时推送的新卡片滑入；决定处理后原地变为"已处理"。

### 8.2 任务详情：「等你决定」与实时状态（要求 c）

- 数据：`GET /np/inbox?kind=decision&resolved=false&issueId=<id>`（服务端新增 `issueId` 过滤）。每条待我决定项一张决定卡；没有就不渲染整个区块。
- 决定卡：琥珀色条 + 类型标题 + 一句事实 + **被决定的完整内容** + 紧贴下方的动作行 + "在收件箱中查看"。本次访问里处理掉的卡片折叠成一行"✓ 已验收通过"，可展开回看。

| 类型                          | 被决定的内容                                                                               |
| ----------------------------- | ------------------------------------------------------------------------------------------ |
| 交付待验收 `review_requested` | Agent 最近一条评论全文（Markdown）+ 最近一次运行结果 + PR 卡片                             |
| Agent 受阻 `agent_blocked`    | Agent 最近评论（受阻原因）+ 失败原因                                                       |
| 审批 `approval_pending`       | 变更 从 → 到、申请人、审批人、申请时间                                                     |
| 执行者建议 `proposal_pending` | 每条建议（可逐条采纳 / 驳回）                                                              |
| 知识建议 `knowledge_proposal` | 文档、理由、摘要；更新类显示与当前版本的行级差异（绿增红删、长的未变段落折叠），可切换全文 |
| PR 待合并 `pr_review`         | PR 卡片                                                                                    |

- 动作层级：主动作是唯一的实心按钮且排第一，其余请求类描边，驳回为红，导航类（改派、打开）为文字按钮。任务页上去掉"打开任务"。与收件箱共用 `DecisionActionsBar`、`useDecisionRunner`。同一类型可以有自己的措辞（`np.decision.actions.<type>.<key>`，如交付的"验收通过 / 打回并留言"）。
- 被决定卡覆盖的审批卡、执行者建议卡不再在下方重复出现。
- **谁在动**：有运行中的运行时，标题下的信息行右侧显示 `NpLiveRun`（Agent 头像呼吸环 + "正在工作 · N 分钟"），点击打开执行过程。
- **空区块不占地方**：没有描述时是一行"暂无描述 · 编辑描述"；子任务为空时折叠成一行虚线"子任务 · 无 [AI 拆解] [+ 新建子任务]"；PR 与依赖为空时不渲染，由描述下方的"添加（+ 前置依赖）（+ 关联 PR）"唤出，有内容后才成块显示。审批、执行者建议为空时本就不渲染。
- 右栏小卡片：属性（执行者显示头像 + 名字）、运行记录、参与者与关注者、详情、用量。
- 评论框：顶部"评论 / 备注"两个标签（备注 = `/note`，不唤醒任何人）；触发预览是评论框下的提示块（会唤醒 Agent 时为主色）；底行左侧"⌘ Enter 快速发送"，右侧主按钮。

### 8.4 看板与任务列表

- 任务、我的任务默认显示**看板**；列表 / 看板的选择按页面记在 `localStorage`（`nocoproject:issues-view:<page>`，读写都包在 try/catch 里），URL 的 `?view=` 优先。
- 看板占满视口：列 18rem、`rounded-xl bg-muted/40`，列头 = 深色圆点 + 状态名 + 计数；每列自己滚动。
- 卡片：编号（等宽）+ 优先级标签；标题最多三行；依赖 / 子任务计数；标签；底行 = 负责人头像 + 执行者（Agent 带呼吸环）+ 截止日或更新时间。Agent 运行中的卡片左侧有 2px 主色条和"工作中"脉冲。
- 表格见 §1.5。

## 9. 状态与文字

### 9.1 加载、空、失败

| 状态   | 规则                                                                                              |
| ------ | ------------------------------------------------------------------------------------------------- |
| 加载   | 形状贴近内容的骨架（表格 = 行、看板 = 列、详情 = 标题 + 块、收件箱 = 卡片）                       |
| 空列表 | `NpEmpty`：图标 + 一句标题 + 一句事实 + 可选的创建按钮；虚线边框                                  |
| 空区块 | 不占地方（§8.2）                                                                                  |
| 失败   | `NpLoadError`：本地化原因；403 不给重试，404 给"返回列表"                                         |
| 反馈   | 显式写操作成功失败都 toast；属性栏行内编辑只在失败时 toast；决定成功 toast "已{{动作}}：{{标题}}" |

### 9.2 空值

表格、看板卡、属性栏里的空值（无优先级、无执行者、无负责人、无日期、无项目）一律显示灰色 "—"（屏幕阅读器仍读出"无优先级"等），不写"无优先级 / 未指派"这类字样。可编辑控件的下拉列表里仍保留"无项目"之类的选项名。

### 9.3 文案

界面文字陈述事实和动作，不解释界面。禁止"在这里可以…""下面是…""就在这里决定…"这类句子；空状态的一句说明写事实（"Agent 开工前会读这里的约定"可以，"点击这里新建"不行）。

## 10. 深色与浅色

- 颜色只用令牌：中性色在主题预设里，语义色在 `np-tones.css` 里，都各有浅深两套。
- 深色靠明度分层；标签在深色下是半透明的暗淡底 + 提亮的文字，不发光。
- 每次改动在两种模式、两个预设下都截图检查（§11）：`pnpm build && pnpm screenshots` 在本机一次性预览上生成全套（`docs/dogfooding.md`"看效果"）。
